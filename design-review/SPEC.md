## 1. Решение по треду (`shared/decision.ts`)

```ts
type Decision = 'reply' | 'read' | 'event' | 'later' | 'clear' | 'unsubscribe' | 'people' | 'automated';
interface ThreadDecision {
  decision: Decision;
  reason: string;                 // одна короткая фраза для строки списка; '' если сказать нечего
  source: 'rule' | 'model' | 'user';
  protected: boolean;             // true: никогда не попадает в групповое действие и в правила отправителя
  laterAt?: string | null;        // предложенное время для 'later'
}
```

Сигналы треда (`ThreadSignals`) считаются при сборке треда из сообщений и хранятся вместе с тредом:
`hasCalendarInvite`, `inviteNeedsAnswer`, `hasListUnsubscribe`, `hasOneClickUnsubscribe`, `listId`,
`isBulk` (Precedence bulk/list/junk), `isAutoSubmitted`, `fromUser` (последнее сообщение отправил сам пользователь).

**Детерминированный слой** (работает всегда, без модели), первое совпадение выигрывает:

1. `inviteNeedsAnswer` → `event`, protected.
2. Письмо безопасности (локальная часть или имя отправителя содержит `security`, либо тема про sign-in / password /
   verification code / 2FA / suspicious) → `read`, protected.
3. Отправитель не автоматический → `people`, protected. Автоматический — если есть любой из признаков:
   `isAutoSubmitted`, `isBulk` (только `Precedence: bulk | junk`), one-click отписка, адрес отправителя совпадает
   с адресом самой рассылки, локальная часть адреса из набора
   `noreply, no-reply, donotreply, do-not-reply, notifications, notification, mailer-daemon, bounce, alerts, updates, news, newsletter, billing, bookings, tracking, receipts, info, hello, offers, deals, members, orders, statements, announce, announcements`
   (сравнение по границам слов, `comments-noreply` тоже считается), либо категория Gmail `CATEGORY_PROMOTIONS / SOCIAL / UPDATES`.
   Голый `List-Id`, `Precedence: list`, обычный `List-Unsubscribe` и категория `FORUMS` отправителя автоматическим
   **не делают**: письмо человека в дискуссионную рассылку остаётся `people` (исправлено по итогам ревью).
   Бесплатные почтовые домены (gmail.com, outlook.com и т.п.) не считаются «своим доменом» аккаунта.
4. Автоматическое письмо с домена самого аккаунта (внутренние рассылки и объявления) → `read`.
5. `CATEGORY_PROMOTIONS` и `hasOneClickUnsubscribe` → `unsubscribe`.
6. Массовая рассылка (`isBulk` или `hasOneClickUnsubscribe`) → `clear`.
7. Остальное автоматическое → `automated` («не разобрано»).

**Слой модели** только уточняет: `people` → `reply | read`; `automated` → `later | clear | read`; `clear` → `later | read`.
Модель никогда не переводит protected-тред в `clear` / `unsubscribe` / `later` и не трогает `event`.
Причина (`reason`) от модели — до 120 символов. Ответ модели валидируется; при любой ошибке остаётся решение правила.

**Слой пользователя**: ручной перенос (`V`) сохраняется как поправка для треда (`source: 'user'`) и побеждает оба слоя.
Поправка действует на этот тред; правило на отправителя — только отдельным явным согласием (раздел 7).

Кэш решений модели — таблица `thread_decisions (account_id, thread_id, last_message_id, decision, reason, source, later_at, model, created_at)`,
ключ `(account_id, thread_id)`; запись устаревает, когда меняется `last_message_id`.

Обязательный тест `tests/decision.test.ts` на 28 письмах рабочего ящика из `dataset.cjs` (скопировать нужные поля в фикстуру):
без модели — People 8, Read 4 (Deploy freeze, People newsletter, SSO, …по правилам), Event 2, Automated 9, Clear ≥ 4, Unsubscribe ≥ 2;
ни одно письмо от человека, письмо безопасности или приглашение не получает `clear / unsubscribe / automated`.
Точные числа зафиксировать по фактическому результату правил и перечислить в тесте поимённо.

## 2. Инбокс секциями

- Сплиты (`SplitTabBar`, вкладки Important / Purchases / LinkedIn / Automation / Other) с почтового экрана убираются.
  Пользовательские категории и их настройки не удаляются из кода и данных, но в инбоксе не показываются.
- Очередь своя у каждого аккаунта. Unified Inbox (`⌘0`) остаётся доступным, по умолчанию не открывается.
- Заголовок: `Inbox` и `N left` — число тредов во входящих, а не непрочитанных.
- Порядок секций: с моделью `Reply, Read, Event, Later, Clear, Unsubscribe`; без модели
  `People, Read, Event, Automated, not sorted, Clear, Unsubscribe`. Пустая секция не показывается. Внутри — по времени, новые сверху.
- Строка секций `Reply`/`People`: отправитель, тема, время; второй строкой причина со значком агента (если есть).
  Остальные секции — одна строка: отправитель, тема — причина, чип действия (`Yes`/`No` у приглашения, время у `Later`).
- `Clear` и `Unsubscribe` по умолчанию свёрнуты в одну строку: число и перечень отправителей.
- Список остаётся виртуализированным; заголовки секций — такие же элементы списка.
- Справа от списка, когда тред не открыт, — панель «Prepared for you»: счётчики по секциям и подсказка по клавишам.
- Когда входящие пусты — экран итога: что отправлено, заархивировано, отложено, от чего отписались (по журналу действий
  за сегодня), ссылки на `Later` и `Waiting`.
- Переключатель ящиков: `Inbox, Later, Waiting, Drafts, Sent, All mail, Trash, Spam, Muted`.
  `Later` — треды с напоминанием; `Waiting` — отправленное без ответа (существующие Reply Pipeline / Follow-up Radar);
  `All mail` — всё, кроме Trash и Spam.
- Экраны `Today`, `Privacy & Cleanup` и боковая AI-панель как постоянная колонка убираются из навигации.
  Их данные и сервисы остаются. Вопрос агенту — через палитру `⌘K` («Ask Dumka»), ответ во всплывающей панели поверх.

- Над списком, под заголовком — строка переходов по секциям (добавлена 2026-11-14 по просьбе владельца: до нижних
  секций приходилось долго листать). Ссылка на каждую непустую секцию с её числом; клик прокручивает общий список
  к секции и ставит фокус на её первую строку, **ничего не фильтруя**: очередь остаётся одной, `J/K` и `N left` не меняются.
  Отмечена секция, где сейчас находится фокус или верх списка. `Clear` / `Unsubscribe` при переходе не раскрываются.
  С открытым тредом список только прокручивается. Не помещается по ширине — одна кнопка с меню тех же секций.
  `]` / `[` — следующая / предыдущая секция. Строки панели «Prepared for you» ведут туда же.
  Вкладками-фильтрами это не делать: они дробят очередь так же, как убранные сплиты.

### Групповые действия

- `⇧E` на секции `Clear`: если секция свёрнута — раскрыть; если раскрыта — архивировать все её строки.
  Состав фиксируется в момент раскрытия: пришедшие позже письма в него не входят. Один `Z` возвращает весь пакет.
- `⇧H` на секции `Later`: отложить все её строки на предложенное время (по умолчанию завтра 09:00 по местному времени).
- Групповых действий для `Reply`, `Read`, `People`, `Event`, `Automated` нет. Protected-треды в пакет не входят никогда.
- `V` — перенести тред в другую секцию (поповер со списком секций, выбор цифрой или стрелками).

## 3. Тред, ответ, отправка

- Колонка Agenda (`RightContextPanel`) с почтового экрана убирается; календарь — отдельный раздел из левой панели.
  На почтовом экране не больше трёх колонок: rail, список, чтение.
- Шапка треда: тема отдельной строкой; четыре подписанные кнопки `Reply R`, `Archive E`, `Later H`, `More` (остальные действия — в меню).
- Над длинным тредом (больше 5 сообщений), если есть модель, — блок сводки из 2–4 пунктов; запрашивается при открытии, кэшируется.
- Редактор ответа закреплён внизу области чтения, не выше 45% её высоты, со своей прокруткой; строка кнопок всегда видна.
- Черновик модели (раздел 5) появляется прямо в редакторе с пометкой `Draft written by the model`.
  По умолчанию он пишется только по кнопке `Draft a reply` (`⇧R`) в строке ответа и не отправляется сам.
  Поздний ответ модели не перезаписывает текст, который пользователь уже начал править.
- `⌘↩` — `Send and archive` (по умолчанию) или `Send`, по настройке аккаунта «After sending a reply»; `⌘⇧↩` — противоположное.
  После `Send and archive` тред уходит из входящих сразу и открывается следующий.
- Отмена отправки 10 с сохраняется. Новая отправка во время окна отмены **не игнорируется**: предыдущая отправка
  фиксируется немедленно, новая получает своё окно. Завершение отправки меняет только свой тред
  (исправить устаревшее замыкание `useDraftsState.ts:691,703`).
- `Esc` в редакторе сохраняет черновик и показывает тост `Draft saved`.
- Приглашение: `Y` / `N` на строке или в открытом треде отвечает организатору сразу, без подтверждения
  (решение владельца), затем архивирует тред. Нет доступа к календарю — кнопка `Connect Calendar` вместо ответа.

## 4. Первый запуск, синхронизация, поиск

- При подключении аккаунта запрашиваются области Gmail **и календаря** одним согласием. Из ответа токена берётся
  фактически выданный `scope`; календарь включается только если его области выданы.
- Сразу после входа главный процесс запускает синхронизацию этого аккаунта. Пока первой синхронизации не было —
  состояние `Fetching inbox…` (не `Ready` и не `Clear inbox split`), с первыми строками по мере прихода.
- Индексация старой почты идёт сама в главном процессе: страница за страницей с сохранённого курсора, с паузой между
  страницами, не блокируя интерактив; пауза при офлайне и ошибке авторизации, продолжение после перезапуска.
  Прогресс публикуется в рендерер: `Indexing older mail, N threads`.
- Нет файла OAuth-клиента — на стартовом экране объяснение (что это и где должен лежать файл) вместо тоста «Please try again».
- Поиск: пауза ввода 80 мс вместо 250; устаревшие ответы отбрасываются; поиск по всей локальной почте; у результата
  чип местонахождения (`Inbox / Archived / Sent / Later`); пока индексация не закончена — строка
  `Older mail is still being indexed`. Панель фильтров — поповер поверх списка, закрывается первым `Esc`.

## 5. Агент

- Агент работает на месте: причина в строке списка, сводка над длинным тредом, черновик в редакторе.
- **Фоновая работа модели выключена по умолчанию** (решение владельца от 2026-11-12). Пока она выключена,
  модель вызывается только по действию пользователя: сводка при открытии длинного треда, `Draft a reply`, Ask Dumka.
  Входящие при этом сортируются правилами на этом Mac (набор секций «без модели»).
- Включается в `Settings → AI model → Sort new mail with the model in the background` (`ai.backgroundSorting`),
  с переопределением на странице аккаунта. При включении на экране всегда виден провайдер и модель фоновой работы
  (`ai.automationProvider`, `ai.automationModel`); они могут отличаться от модели для чата.
  Подготовка черновиков заранее — отдельный выключатель внутри (`ai.proactiveDraftsEnabled`), тоже выключен.
- **В приложении нет зашитых идентификаторов моделей** (решение владельца от 2026-11-12): они быстро устаревают.
  Модель всегда берётся из настроек. Список для выбора приходит от провайдера (`GET /models` с ключом пользователя),
  обновляется раз за запуск и показывается от новых к старым; можно вписать имя вручную. Ничего не предлагается и не
  подставляется за пользователя. Провайдер с ключом, но без выбранной модели, считается ненастроенным (`Missing model`),
  запросы к нему не уходят. То же для модели эмбеддингов семантического поиска.
- Когда фон включён, делает сам (локально, Gmail не трогает): решения по тредам, причины, черновики.
- После одной клавиши и с отменой: archive, later, перенос между секциями.
- Только по явному действию пользователя: отправка, отписка, ответ на приглашение, удаление.
- Фоновая подготовка, когда она включена, провайдер настроен и для аккаунта разрешена отправка текста модели:
  решения — пачками до 12 тредов входящих; черновики — только для секции `Reply`, не больше 5 за проход,
  один запрос одновременно, с отменой при смене аккаунта. Без провайдера ничего не запрашивается.
  Просматриваются только 100 самых свежих тредов входящих на аккаунт; решение по треду запрашивается один раз.
- Ответ модели стримится в интерфейс там, где провайдер это поддерживает; запрос можно отменить.
- Ошибка модели: в интерфейсе `Couldn't reach the model` + `Retry`, инбокс переходит в режим без модели;
  сырой текст исключения — только в журнал (Logging).
- Без провайдера: AI-кнопки и «Prepare draft» не показываются; в шапке списка пометка `Basic sorting`
  и одна строка-приглашение подключить модель (ключ вводится в коротком листе: провайдер, ключ, проверка).

## 6. Отписка

- Только через лист подтверждения: отправители (имя, адрес, способ — one-click или mailto), текст
  «This sends a request to each sender and cannot be undone from Dumka Mail», галочка «Also archive their messages».
- Подтверждение — `⌘↩` или кнопка; `Esc` отменяет. После — тост, в котором `Undo` относится только к архивации.
- Нынешний клик `Unsubscribe` в письме открывает этот же лист с одним отправителем.

## 7. Правила отправителей (делается последним)

- После трёх подряд подтверждений `Clear` для одного отправителя без единого возврата — предложение
  `Always archive mail from <sender>?` Правило создаётся только явным согласием, на конкретный аккаунт.
- Правило применяется при синхронизации: новые письма отправителя архивируются и попадают в свёрнутую строку
  `Handled for you (n)` вверху инбокса с возвратом каждого письма и всех сразу.
- Правило не применяется к protected-тредам и к письму, которое детерминированный слой не считает `clear`.
- Два возврата писем одного отправителя отключают его правило; главный процесс проверяет это сам и не применяет
  такое правило, даже если настройки ещё не обновились. Отмена в течение 15 с после собственного архива возвратом
  не считается. Список правил — на странице аккаунта.

## 8. Настройки

- Навигация настроек: `Accounts` (по строке на аккаунт) и `App`: `Appearance`, `Shortcuts`, `AI model`,
  `Privacy and data`, `About`; всё остальное существующее — под `Advanced` (ничего не удалять).
- Страница аккаунта: Signature; After sending a reply; Notifications (`People only / All / None`);
  What the agent may do on its own (`Prepare only` / `Prepare and apply my sender rules`);
  Sort new mail with the model in the background (по умолчанию выключено); Mail text may be sent to the model; Sender rules; Calendar (подключён / Connect); Reconnect / Disconnect.
- У каждого параметра аккаунта пометка `App default` или `Customised` и сброс к умолчанию.
  Хранение: `settings.accountOverrides[accountId]`, недостающее наследуется из общих настроек; миграция без потери значений.

## 9. Клавиши

Существующие привязки не меняются. Добавляются: `⇧E`, `⇧H`, `Y`, `N`, `V`, `⌘⇧↩`, `⇧R` (черновик ответа от модели).
Справка по клавишам и палитра команд обновляются. Буквенные клавиши не срабатывают в редакторе и в полях ввода.
