## Изменение после первого ревью владельца (2026-11-12)

Владелец попросил: автоматическая обработка писем моделью выключена по умолчанию, черновик ответа — по кнопке,
модели по умолчанию актуальные, а при включении фона — понятный выбор модели.

- `ai.backgroundSorting` (по умолчанию `false`, переопределяется на странице аккаунта) закрывает фоновые решения;
  `ai.proactiveDraftsEnabled` (по умолчанию `false`) — черновики заранее, работает только вместе с первым.
  Проверка стоит в `main/agentPrepCore.ts` перед каждой пачкой и перед каждым черновиком, и в старом пути `main/agentic.ts`.
- С выключенным фоном инбокс использует набор секций «без модели»; сохранённые решения модели игнорируются.
- В строке ответа появилась кнопка `Draft a reply` (`⇧R`): модель пишет черновик в редактор, отправка остаётся отдельным шагом.
- `ai.automationProvider` — отдельный провайдер для фона (можно дешёвую или локальную модель). Идентификатор модели
  для чата никогда не подставляется чужому провайдеру.
- Зашитых идентификаторов моделей в приложении нет (второе уточнение владельца в тот же день). Убраны модели по
  умолчанию у всех провайдеров чата и эмбеддингов и списки «известных» моделей. `shared/aiModelCatalog.ts` только
  фильтрует и упорядочивает список, который отдал провайдер; `ModelPicker` ничего не предлагает и не выбирает сам.
  Провайдер с ключом без выбранной модели получает статус `Missing model`: функции модели скрыты, запросы не уходят.
  Формат запроса к Gemini (уровень размышления, инструкция для эмбеддингов) определяется по номеру поколения выбранной
  модели, а не по списку имён. Тест `tests/aiModelCatalog.test.ts` падает, если идентификатор модели снова появится в коде.
- Проверено на стенде: с настроенной моделью и выключенным фоном за 40 секунд после подключения ящика — 0 запросов к модели;
  `⇧R` — ровно один запрос черновика; включение фона — запрос списка моделей и пачки решений, черновики не запрашиваются.

  «ключ есть, модель не выбрана»: её нужно один раз выбрать в `Settings → AI model`.
- Для эмбеддингов модель и размерность вводятся вручную: списка от провайдера в этой панели нет.
- Подсказки при наборе письма (Smart compose) включены по умолчанию и тоже обращаются к модели; этой правкой не затронуты.
- **Не проверено на настоящем Gmail и настоящей модели.** Всё проверялось на поддельном бэкенде и скриптованной
  модели с идеальными ответами. Качество решений и черновиков реальной модели неизвестно.
- Ответ на приглашение на стенде шёл запасным путём (создание события); изменение существующего события в настоящем
  календаре не проверялось. Офлайн ответ не ставится в очередь.

- Кнопка «New mail» (новые письма не двигают список под курсором) не сделана.
- Предложение правила и «Handled for you» показываются только для одного активного аккаунта, не в Unified.
- Светлая тема, узкое окно и второй аккаунт после переделки визуально не проверялись (только тесты).
